# Supply package

Distributor connectors, the call budget, and (as they land) parts, stock
history, assessment and part intelligence. Read `AGENTS.md` at the repository
root first.

## What exists

| Module | Role |
| --- | --- |
| `vocabulary.py` | `Status`, `Lifecycle`, `Packaging`. The only wording any surface uses. |
| `models.py` | Provider-neutral `Offer`, `PriceBreak`, `Incoming`, `PartMatch`, `PartData`. Validate on construction. |
| `providers/base.py` | The provider contract: `ProviderSpec` (with `hosts`, the only hosts its HTTP client reaches), `ProviderConfig` (with `on_limits`, which Prism sets), the `SupplyProvider` protocol, the capability protocols checked with `isinstance` (`BatchSearch`, `FamilySearch`, `ConnectionCheck`, `ChangeNoticeReader`, `SubstanceReader`, `SubstituteReader`, `CallCounting`), `ProviderError` subclasses. Adding a distributor is one adapter module on `providers/http.py` and a `register` line. |
| `providers/http.py` | `HttpProvider`, the base every web-API adapter uses: the HTTP client limited to the spec's hosts, the pacer the account's connectors share, the clocks, `request` (paced and counted) and `authorised` (one new token when the service refuses the one it had); `ClientCredentials` is the OAuth client-credentials token. `calls` counts every request, token requests and repeats included: the poller and the discoverer charge what an operation made beyond what it paid for up front. |
| `providers/template.py` | A complete adapter for a made-up API, not registered: what a new distributor copies. The contract kit runs it like a built-in. |
| `providers/registry.py` | Provider lookup. Built-ins register at import; plugins load from the `prism.supply_providers` entry point. |
| `providers/tme.py` | TME API v2: OAuth client-credentials token (kept until shortly before it expires), `/products?mpns[]` to find listings, `/products` plus `/products/data` for offers (two calls a batch of 50). The storefront is the country. Gross prices are turned net. |
| `providers/mouser.py` | Mouser Search API V1: `search/partnumber` with up to 10 numbers per call, `Exact` matching, calls spaced 2 seconds apart. Errors arrive in a 200 answer. |
| `providers/digikey.py` | DigiKey Product Information V4, from its Swagger file: OAuth client credentials, keyword search, one product-details call per SKU (one SKU is one packaging), stock pooled. Not yet run against the live service. |
| `providers/arrow.py` | Arrow Pricing & Availability (Item Service v4, `search/list`, GET with the key inside `req`): up to 100 numbers a call, every orderable line (`sourceParts[]`, per region with its own currency) a listing numbered `partNum\|sourcePartId`, prices never converted by Arrow, `vipPrice` ignored. From the documentation only; not yet run against the live service. |
| `providers/farnell.py` | Farnell, Newark and element14 Product Search REST: manufacturer-number search, one SKU per call, the connector names the store and the currency. Not yet run against the live service. |
| `providers/jlcpcb.py` | JLCPCB (assembly) as a CSV-fed connector: the same uploaded file as `csv_provider`, under the `jlcpcb` key, with every offer marked marketplace so no total counts it. Assembly-only; the file's optional `jlc_library` and `jlc_preferred` columns become facts (B, E, a star). Unmetered. |
| `providers/lcsc.py` | LCSC as a CSV-fed connector: the same uploaded file as `csv_provider`, under the `lcsc` key, so saved listings and BOM links keep their provider. Unmetered. |
| `providers/normalise.py` | What several distributors' answers share, read one way: `price_breaks` (pairs parsed, first price per quantity, ascending), `rohs_word` (plain wording), `packaging_word` (most specific word first) and `link` (a protocol-relative address made https). A distributor's own codes and field names stay in its adapter. |
| `providers/text_values.py` | Reads numbers sent as display text: "1,234 In Stock", "0,52 EUR", "42 Days". |
| `providers/unrecognised.py` | Logs once a status or wording an adapter does not know, so a new one that matters gets noticed. |
| `providers/fake.py` | Deterministic simulated market for tests, development and demos. Off unless `SUPPLY_ENABLE_SIMULATED_PROVIDER` is set. |
| `project_parts.py` | A project's parts list a page at a time: each part with its BOM lines for the build, the "needs a look" chips counted over every line, the reference search, the project's own sort columns, and the lines no part matches (`GET /api/supply/projects/{id}/parts`). |
| `progress.py` | `job_progress`: the one shape of a job's progress (`state` running, done, failed or none; `done`, `total`, `failed`, `reason`), used by the project read, the first searches of a tracked project, a one-off check and a release's snapshot. |
| `identity.py` | `match_key`: the lookup key for part numbers. Conservative on purpose: dots and slashes stay. |
| `parts.py` | Manufacturers, their spellings, parts and the other numbers a part is sold under (added by the packaging endings, or by a person in Review). `ensure_part` refuses nobody (a maker nobody has checked is provisional). Functions on a connection; none commit. |
| `makers.py` | `same_maker`: whether two spellings name one maker (same key, seeded spelling, starts with, whole words inside, initials, one lost letter). Never looks at a part number. |
| `settle.py` | Settling a provisional part's maker from the listings of its number, the questions a person answers (`needs_choice`, `choose`, `not_this_maker`, `use_numbers`), and learning spellings (`learn_aliases`, run as the `aliases` task; `undo_alias`). |
| `number_suffixes.py` | The endings makers put on a base number (`number_suffixes` table, editable): packaging ones are added to a part by discovery, grades wait for a person (`kind_of`). A comma and three digits is always packaging. |
| `part_insights.py` | What the history says about each tracked part (trend, days to zero, lead time, holders, repricing, 30-day stock), kept in `part_insights` by housekeeping (`renew`: missing, then marked stale by `freshness`, then older than 20 hours, for up to a minute a run); `KINDS` are the findings the Parts `only` filter and the Insights lists use. The kept facts carry the price trend and `likely_at` (the part's or the workspace's chance that is "likely out", the `likely_out` check's too); housekeeping evaluates the alerts of the parts it renewed. |
| `dashboard.py` | The Dashboard page in one read: figures with 30 days of history (`figure_history`, one value a day), status mix, runway buckets, holders, alerts opened by day, cost per board, recent changes, and what an empty alert list says (connectors, parts with no reading). |
| `work_items.py`, `backend/app/api/supply_work_items.py` | Work items, as `attention` rows of kind `work` whose assignment columns are the item (open until done or rejected; `STATE_SQL` reads the item's state from the row's state and disposition): a decision about a component or a part with an action, owner, evidence notes, the projects it touched when opened (kept, shown only where the caller's role sees them), QA's disposition and a recheck date. Followers open and edit, approvers accept/reject/reopen, the owner, maker or QA marks done. History is the audit trail (`subject_kind = 'work_item'`). Changes nothing in the library or the BOM. |
| `insights_page.py` | The Insights page: counts per finding, the runway scatter, distributor behaviour across all parts, the market overview. Keeps the distributor scorecard for six hours per process (`forget()` in tests). |
| `maker_seeds.py` | The built-in spellings of large makers as rows (`maker_seeds`) an administrator edits; `makers.refresh` reads them. |
| `maker_backfill.py` | Migration 56: sorts the listings that waited under the old rules again. |
| `packaging_auto.py` | Picks the packaging of a tracked part by what its projects buy for (prototypes: smallest order, production: a reel). Never changes a person's pick. |
| `discovery.py` | `DiscoveryService`: sorts a provider's answers into match states (a number the part is sold under and the same maker count; another maker's listing is `near`). Also `pin_listing`, `reject_listing`. |
| `review.py` | Reads the review queue: pending spellings and listings waiting for a person, and what waits for an approver (`to_approve`: waivers, alternates, dismissals). |
| `backend/app/api/supply_review.py` | Review API. Everyone who reads supply data sees the queue; confirming a spelling and pinning or rejecting a listing need admin or qa. |
| `watches.py` | The watchlist: one watch per part, with a stock threshold and a pin to the fastest polling (pins are capped). `follow` is the one way a person follows a part or changes how (tier, rate, threshold, pin, packaging); `add_watch` follows a number Prism has no part for yet. |
| `tiers.py` | Pure rules: when a listing is next due (`next_poll_at`: once in each provider day for daily, a day-changing jitter for weekly and monthly; `stretch` doubles the wait for a calm listing), which comes first when the budget is short (`urgency`), and when to retry (`retry_at`). |
| `tracking.py` | What Prism follows and why: tracked projects, a person's tier choice (`watches.tier`, `rate`, `origin`), watched components' main parts and `part_tiers`, derived from every source with its reasons (`recompute`). Tier 1 is read daily, tier 2 weekly or monthly, tier 3 only on request. |
| `budget.py` | Pure cost model: calls a day one part costs at one provider by tier, rate and listings followed (reads, notices, substances, searches). |
| `admission.py` | Where each followed part is read (`admissions`): admitted while the account's committed share has room, else waiting for room. `sync`, `preview` (runs a change and rolls it back) and `apply` ("track where room", refused when nothing fits). |
| `budget_view.py` | The read behind `GET /api/supply/budget`: shares, spending by kind and purpose, 14 days, what tracking costs, what costs most, and how many tracked parts each connector prices and has still to search. |
| `packaging_picks.py` | One followed listing per part and distributor: the picks waiting, the listings side by side, pick and clear, and "same for similar". Only the picked listing is read and counted; `admission.sync` drops a pick whose listing is no longer counted. |
| `oneoff.py` | Check once: a request lists parts, `read_request_work` has a row for each part and distributor; the worker searches and reads them from the pool, then from spare budget, without tracking anything. |
| `packaging_picks.py` | One followed listing per part and distributor: the picks waiting, the listings side by side, pick and clear, "same for similar". Only the picked listing is read and counted; `admission.sync` drops a pick whose listing is no longer counted. |
| `oneoff.py` | Check once: `read_requests` list parts, `read_request_work` has a row per part and distributor; the worker searches and reads them from the pool, then spare budget, without tracking. |
| `project_supply.py` | The project Supply tab: the stored BOM looked up (parts with tier, waiting and note counts), the builds the project put on the plan, release snapshots judged against today for what changed since, and the line notes. Calls no distributor. A tracked project's usual-build answer is kept in `supply_project_rollups` (`usual_rollup`, `refresh_rollups`): it is current while `freshness` finds no mark it did not see for its project, one of its parts or every project, and it is under an hour old. |
| `alert_rules.py` | Per-part alert rules: muted kinds, the price rise that matters, a target price, the chance that is likely out. The assessment reads the figures (they are its `price_up`, `target_price_missed` and `likely_out` checks' limits); a muted kind is a standing `mute` decision (`attention`), and `alerts` drops it once an approver's (a writer's waits as `muting`, `decide_mute`). |
| `attrition.py` | The package class of a footprint (small passive or other); the percent of each is the workspace's `spares` setting. Used when a lookup asks for `attrition_percent: null`. |
| `cross_reference.py` | Alternatives with the same value, graded ratings met, similar (ratings the candidate doesn't list are unknown, never met), other package, or fails a rating, from canonical parameters and the distributor category; `grade` is pure. No grade claims interchangeability; no footprint, pin or operating-condition comparison. |
| `trade.py` | ECCN and tariff codes distributors state for a project's parts, disputes and gaps, and its CSV. |
| `clock.py` | Supply's one clock: what supply writes or compares comes from a clock the caller passed in (a job's, a test's) or `clock.now()`, never the database's `NOW()` nor `datetime.now()`. Every stored time is set by the write, column defaults are only a fallback; `backend/tests/test_supply_one_clock.py` fails on either. |
| `accounts.py` | Connectors on the same credentials are one account (keyed hash), a row of `supply_accounts`: one budget, reserve and reset time, one ledger, one pacer, one job. A connector with no credentials is its own account (same id); new credentials move a connector between accounts (`rekey`), and an account goes with its last connector. |
| `pacing.py` | Jittered gaps between calls (0.75 to 1.5 times about half the published rate), shared per account (and between processes through `pace_state`), doubled for a day after a rate limit. |
| `settings.py` | The workspace's settings, one typed section each and one `supply_settings` row each: `assessment` (rules in `assessment/settings.py`), `pricing` (base currency, price quantity, preferred distributors), `alerts`, `spares`, `schedule` (which spare work is on; spare budget, `quota.free_allowance`, is the calls nothing else needs). `load` reads them all in one query; a stored section that no longer fits is its default. Saves and resets are audited per section, and a new price quantity or base currency forgets the kept prices. The only reader and writer of `supply_settings`. |
| `counted.py` | Which listings count, in one place: `STATES` (exact and manual) and its database copy `supply_counted(match_state)`; `listing_sql` (a counted match at an enabled connector, read: a pick that limits reads leaves the others out); `priced_sql` (the picked listing prices the part at its distributor). |
| `freshness.py` | When a kept answer (part summary, part insight, part forecast, project rollup) is stale: one table of marks, `supply_dirty(kind, key, xid)`, written by row triggers made from `schema/derived.SOURCES` (which tables each kind is worked out from, in one place; an update marks only when it changes the row, so no statement triggers on busy tables) or by `mark` for a change no table shows. A kept answer records the snapshot it read (`seen`, `snap`, `own`) and is stale when a mark of a kind it reads (`READS`) for its key or `*` came from a transaction that snapshot did not see, or its own: a long transaction does not make answers stale. `trim` removes marks nothing can still depend on. |
| `offer_rules.py` | Rules read off a part's counted offers, one function each: `lead_time_of` (shortest positive non-marketplace quote, of offers holding stock first) and `rohs_verdict` (the offers decide; the RoHS status stated for the part only when no offer says; `compliance.rohs_verdicts` loads both, and the part sheet, Insights, list flag, checks, risk score and compliance draft all use it). Holders are `stock.holders`; the ending lifecycles are `vocabulary.ENDING_LIFECYCLES`; a listing's price on a day at the part's quantity is `prices.on_day`. |
| `stock.py` | A part's stock across distributors, honouring each provider's pooling. Only exact and manual listings at enabled connectors, no marketplace stock. Connectors on one account (`pool_sql`) are one stock pool and one holder. A total is dated by the oldest read it rests on (`as_of`). `packaging_of` is the packaging a part is followed in: its watch's, else a watched component's. |
| `discoverer.py` | Searches for listings of followed parts at the connectors they are admitted at: the first time from the pool (then spare), again every month at tier 1 and quarter at tier 2, found or not. A provider with `search_batch` is asked for a group of parts per call (`lookup_mpns`). Costs budget like any call. |
| `library_match.py` | The library pass: library parts nothing follows are searched once per distributor from spare budget (again after 90 days), batch distributors (`search_batch` ≥ 10) first; others only search what none of those carries. `progress` gives the counts and days left the Connectors page shows. |
| `jlc_catalogue.py` | JLCPCB offers from the jlcparts catalogue (opt-in per connector, `catalogue`): reads the search index, downloads only the shards holding known part numbers, maps rows to `CsvOfferRow`; a manifest version other than `VERSION` stops the import. `csv_import_service.refresh_catalogues` runs it from housekeeping every 12 hours. |
| `trouble.py` | What to do when a provider call fails (rate limit, bad credentials, other), shared by polling and discovery. |
| `component_watches.py` | A standing request to follow a catalog component's main part: `tracking` reads it as a `component` reason (no part watch is made), so stopping it lowers the part. `remove_for_part` is `watches.stop_tracking`'s way of stopping the components a part is the main part of. |
| `bom_comments.py` | Notes on a project's BOM lines, by line key. |
| `demand.py` | What scheduled work (reads due before the reset, searches, budget-sharing notices) still needs of an account today, in calls the way each provider batches. The poll job stores it on the ledger; `quota.free_allowance` leaves it, what is kept for people and a margin alone, and the rest is free for spare work at any hour. |
| `notice_budget.py` | The change-notice allowance of a provider with a quota of its own (DigiKey, 50 a day): counted in `call_counts`, not in the product budget; all 50 may be spent, tracked parts read over the shortest interval that fits, untracked parts last. |
| `part_history.py` | A part's stock and price per distributor over a number of days, carried to each listing's last read, for the part sheet's lines and its larger dialog. |
| `headline_price.py` | The price a part shows in lists: every counted listing priced at the part's quantity and converted to the base currency, as orderable, backorder (with its lead time), last seen or list price (the choice is `pricing.best_offer`), with the range and median over distributors and the price before conversion. A currency without a rate is left out and named. |
| `price_quantity.py` | The quantity prices are read at: the workspace default (a Supply setting, 100) and a part's own (`part_price_quantity`). A change drops the kept summaries and insights of the parts it touches; no distributor is asked. |
| `price_breaks.py` | A listing's price breaks as they changed (`price_breaks_history`), kept by the poller when they differ from the last: the only price history. `price_on` gives a listing's price on a day at any quantity; readings keep stock and terms, not a price. |
| `part_search.py` | One search over library components and supply parts with a part found once (merged by maker and part number), by role. Behind `GET /api/search/parts` and the command palette. |
| `alternates.py` | Parts distributors suggest in place of a part (`part_alternates`): `listed` ones come with an offer read (LCSC, Mouser), `asked` ones from DigiKey's substitutions call. Each provider's set is replaced whole. Not compared with the part. |
| `substitutes.py` | Asking DigiKey for substitutes: on request (once an hour per part, interactive reserve) and automatically once for a tracked part that is ending (committed budget, again after 30 days). |
| `stock_events.py` | Stock-outs and restocks as the poller sees them, with the lead time quoted at the stock-out; a restock ends the open stock-out. |
| `scorecard.py` | Per distributor, on parts two or more list: stock-outs, restocked first, promises kept (quoted lead times and Mouser's dated arrivals), wait said against real, days in stock (counted in the database). Withheld under five events. Also each distributor's open promise on one part. |
| `ending_parts.py` | Library components whose part is ending, with the reasons, last buy date, stock and projects; and the decision kept for each (`component_restrictions`: not for new designs, retired). Proposes only. Components come from `component_parts` (main part or approved alternate). A dismissal (a standing `dismiss` decision, `attention`) hides a component until its part gains a new reason; a writer's waits for an approver (`decide_dismissal`). The list shows as notifications on the Supply Dashboard, with the decisions inline. |
| `forecast/models.py` | Pure model maths: the stock simulation (drain since the last restock, Kaplan-Meier time out of stock, 2,000 futures per distributor), price repricing in 30 and 90 days, the lifecycle rate and chance, and a family's lead-time trend and early warnings. |
| `forecast/inputs.py` | Reads the readings and pooled figures the models take: holders and their similar-part drains, outage models and quote ratios, repricing moves, lifecycle rates and signs, and market series. Each pooled cache is kept against the day and a cheap marker of the rows it pools, so every process works it out again when they change; each has its own `forget`. |
| `forecast/store.py` | Forecasts as kept: stored when made, checked when their day comes, each model's state (learning, shown, paused) from its checks, the words for a chance, the track record, and each part's forecast as its sheet shows it (`supply_part_forecasts`, kept while it is today's and fresh). |
| `forecast/run.py` | The daily make-and-check run, called from housekeeping and `part_insights`; it keeps each part's sheet forecast (`part_forecast`). `backend/scripts/forecast_backtest.py` replays past days. |
| `forecast/views.py` | The part forecast as the screens get it (the kept one at the part's own quantity, worked out only for another or once it is stale), the Dashboard and Insights roll-ups, the panel line, and the Parts list's likely-out filters. |
| `preferences.py` | A person's preferred distributor for a part (`part_preferences`); it orders and marks, and prices the BOM when the setting is on. |
| `trade_marks.py` | Whether a part is export controlled: what distributors state, and a person's mark that wins. |
| `risk_views.py` | The Dashboard and Insights risk views: lifecycle against availability, deadlines, distributor coverage, lifecycle and compliance mixes, lead times, price movers, trade. |
| `providers/packaging_hints.py` | Packaging read from words, and guessed from a SKU or order terms when a distributor says nothing (marked inferred). Whether a provider's packaging is guessed, or is the product's standard one, is on its spec (`guesses_packaging`, `standard_packaging`). |
| `jobs.py` | The `supply_poll` and `supply_tasks` job handlers and `schedule_due_supply_jobs`, which prism-worker runs every minute: one poll job per account with work, and one tasks job when a periodic task is due. |
| `tasks.py` | Periodic work with no distributor call (rates, catalogues, snapshots, learned spellings, component main parts, tracked BOMs, tracking, packaging picks, insights, forecast checks, rollups, retention, inventory sources, account keys, finished jobs), each a row of `supply_task_runs` with its last run, success and error. Each runs in its own transaction; a failure is recorded and logged and the rest go on. |
| `poller.py` | `Poller.poll_connector`: asks for due listings of admitted pairs (the picked listing when one is picked), tier 1 first, in batches within the call budget, and records the answer through `persist.Writer`. `spare=` reads waiting pairs or tier-2 parts early from spare budget. A provider with `groups_by_part` (DigiKey) is asked once per part, with the part's other listings read in the same call. |
| `persist.py` | The one write path for an answer (a poll, a search that brought offers, offers pushed in): normalise (packaging guess, reference price), persist (kept offer, price breaks, a sample only when something changed or the last is a day old, promises, stock events, facts, substances, alternates, change events), derive (urgency once per part) and schedule (next read). What a batch reads is loaded once and the offers, samples, listings and read states go as pipelined statements. |
| `offer_lines.py` | A part's offers as the detailed Parts list shows them: one line for each way of buying (DigiKey cut tape and Digi-Reel on the same terms are one; Mouser's reel inside its price table is its own). Keeps every number; the sheet's listings are untouched. |
| `parts_view.py` | Read models for the Parts screen: the list and one part's detail, with history carried forward day by day. Each part's offer summary and status is kept in `supply_part_summaries`, in typed columns (status, health, stock, lifecycle, unit price in the base currency, read time). The status is the part's assessment without a build to cover; there is no other status (D2). A kept row is worked out again when the clock reaches its `changes_at` (a read falling late, a last date to buy coming close), when `freshness` finds a mark it did not see, when the workspace currency or exchange rates differ from the ones it was priced with (`priced_with`), or when `SUMMARY_VERSION` changes. The list, the part sheet (status, stock, lifecycle, problem, list price) and `summaries_with_offers` (the BOM lookup, the KiCad panel, the assessment) all read the kept summary. The list brings the summaries it covers up to date, then filters, sorts and pages on those columns in SQL, however many parts match. `tracked_states` and `tracked_project_rows` feed the Dashboard from those kept summaries. |
| `attention.py` | One model of what needs a person (D3). `supply_attention`: a row per subject (part or component, each with its foreign key), kind and episode, `pending`, `open` or `resolved`, with a `scope` fingerprinting the condition and assignment columns. `supply_attention_decisions`: acknowledge and snooze of one row (gone when the row resolves or gets worse), and standing decisions per subject, kind and decision: `mute`, `dismiss`, `waive`, `accept` (the status a part is judged against). `open_counts` and `summary` are the counts every page shows: one GROUP BY over open rows nobody quieted. One rule for putting something aside, by permanence (`state_for`): acknowledge and snooze are for writers; dismiss, mute and waive are an approver's, and anyone else's is a proposal (`settle`). |
| `alerts.py` | Alerts on watched parts, as part rows of `attention`: one per part and kind, opened after two looks 30 minutes apart (a lost part opens at once), cleared when the condition clears, acknowledged or snoozed by people. The conditions are the tracked part's unwaived assessment findings (`ALERT_OF_CHECK` names the alert each check raises), at the severity the workspace set, plus a status worse than the one it is judged against. In-app only; nothing is sent anywhere. Evaluated after every read, every watch change and every insight renewal. |
| `insights.py` | Pure: what a part's daily stock history says. Observed net decrease (Theil-Sen slope since the last restock), days to zero and to the threshold, restocks and cadence, and a confidence. A change in how many listings stand behind the figure is cut, never read as a restock. Every answer lists its inputs. |
| `connector_check.py` | Tests a connector with one real call charged to the interactive reserve. Reports in fixed, safe words (never the provider's text), records the result on the connector, and never pauses it. |
| `bom_lookup.py` | Looks a BOM up in supply data without calling a distributor: each line resolves to a part (manufacturer and number, or number alone when unambiguous), reports stock, status, lead time and the cheapest offer that covers the need, and rolls up cost, shortages and "can build N". A line counts its component's approved alternates (`line_alternates`, D2): their stock and offers add up, and the line shows the best status among them. Project lookups pass the catalog readers (`library_readers`) so lines placed by Prism ID take their component and the rest say whether the library has them. Also watches the parts on a BOM. |
| `backend/app/api/supply_bom.py` | BOM lookup (readers) and watch-all-lines (admin, designer). |
| `fill.py` | Fill from distributor: asks the connected distributors for a part number and, for one picked candidate, its description and datasheet. Spends the interactive reserve; writes nothing to the catalog. |
| `backend/app/api/supply_fill.py` | Fill search and details (admin, designer). |
| `backend/app/services/supply/assessment/settings.py` | Check ids, labels, areas, default severities and thresholds: the `assessment` section of `settings.py` (the late read limit counts from the part's schedule). |
| `backend/app/services/supply/assessment/checks.py` | Findings from a part's facts: lifecycle, stock (and the watch's threshold), what is coming (the forecast's chance once its model is shown, else the drain), the price rising or over its target, change notices, lead time, RoHS, age. Each finding carries the figures its alert shows (`detail`). Pure rules; `changes_at` is when the clock alone would change them. |
| `backend/app/services/supply/assessment/risk.py` | Five risk sub-scores, 1 good to 5 bad, each with its reasons. What a check decided (nothing in stock, RoHS, REACH) is read from its unwaived finding. |
| `backend/app/services/supply/assessment/health.py` | Health 0 to 10, status, and the quantity-weighted BOM roll-up. |
| `backend/app/services/supply/assessment/waivers.py` | Proposing, approving and applying waivers, as standing `waive` decisions (`attention`); a waiver holds while its condition does (same scope), and one approved for another condition is `outdated`. Release checks and snapshots read `holds`. |
| `backend/app/services/supply/assessment/service.py` | Gathers a part's facts and runs the pipeline. Reads only; no distributor calls. |

## Rules

- **Supply data never enters component revisions.** Revisions are hashed;
  prices change daily.
- **Only `exact` and `manual` listings count** toward stock and price. A person's
  decision (`manual`, `rejected`) is never overwritten by discovery, and an
  `exact` listing is never downgraded by a search for a different part.
- **A decrease in stock is called "observed net decrease", never consumption.** Transfers and
  reporting caps look the same. A rupture warning needs at least medium confidence and no regular
  restock due first.
- **Usage reads are role-aware.** A project hidden from a role by its folder never shows in that role's
  "Used in" or "In use"; `usage.VISIBLE` is the filter and every read passes the caller's role.
- **Only approvers introduce a manufacturer.** A designer watching a part must pick a
  manufacturer Prism already knows (`ensure_manufacturer(may_create=False)`), so a stray
  "TI" cannot become a second Texas Instruments.
- **Approval is a person's.** "Is this caller an approver" is `supply_access.is_approver` (policy
  `supply_approve`, human-only), never a role comparison: an agent with QA's role proposes, it never approves.
- **A job is queued only when the connector can spend a call now** (`jobs._has_budget`),
  and a repeated provider failure rests the connector. Neither may become a job a minute.
- **A manufacturer argument is a hint, never a filter.** Prism decides who is the
  same manufacturer, using its alias table.
- **The manufacturer part is the spine.** A feature that needs part data reads
  it from there. No feature keeps its own copy.
- **Adapters follow the provider's published API description**, and their fixtures say where
  they come from (`backend/tests/fixtures/supply`). Replace a schema-shaped fixture with a
  recorded answer when one is available.
- **Network providers do not touch the database and do not log credentials.**
  They return models or raise `ProviderError`. Callers decide what to store.
  The CSV provider is the one that reads a table, and only its own.
- **Credentials go through `credentials.py` only.** Reads return which
  credentials are set, never their values. There is no plaintext fallback.
- **Every outbound request goes through `http_client.py`**, which validates
  with `egress.py` on each redirect and connects to the address that was
  checked. Do not call `requests` directly from a provider.
- **Failures retry on their own schedule** (`tiers.retry_at`), never the tier's. A
  rate limit holds the whole connector off; rejected credentials pause it.
- **Quota is a budget, not an error.** Running short delays polling and shows
  data age. Spend only through `ledger.try_spend`.
- **Audit identity comes from the session**, passed in as `actor`. Never take
  it from a request body.
- **Supply tables are catalog tables.** Every table, index, trigger and function
  is prefixed `supply_` (`backend/tests/test_supply_schema_names.py` checks). Until supply is first
  released, a schema change is an edit to `schema/` (and local databases are rebuilt); from then on it is
  a new step in `backend/app/services/catalog_schema_migrations.py`, never an edit to `schema/`.
- **Role-aware lookups only** when supply data is joined to projects.

## Tests

`backend/tests/test_supply_foundation.py`, `backend/tests/test_supply_csv_format.py` and
`backend/tests/test_supply_http_client.py` need no database or network.
`backend/tests/test_supply_connectors_postgres.py` and
`backend/tests/test_supply_connectors_api.py` need `PRISM_DATABASE_URL` and use a
disposable schema. Provider tests use recorded fixtures, never live
calls. Every web adapter, and the template, runs through the contract kit
(`backend/tests/supply_provider_kit.py`, in `backend/tests/test_supply_provider_contract.py`): the real HTTP client
over a replayed recording, checking the spec, shapes, paging, the call meter, errors and hosts. A new adapter adds a
class there; the contributor page is `website/src/content/docs/contribute/add-a-distributor.md`. Frontend tests are `*.test.ts(x)` beside the code.
