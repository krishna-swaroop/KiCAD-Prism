# KiCAD Prism v4.0.0-alpha

This release brings together the features and fixes added since v3.0.2-alpha. We are
releasing them as **v4.0.0-alpha**, skipping the planned v3.1 release. Users do
not need to install an intermediate 3.x version.

**Existing catalogs need attention before upgrading.** The new catalog format
is called epoch 2. If your catalog still uses the older format, back up the
whole installation and verify the backup. Export and verify the non-CERN
components you want to keep, then run the checks for import problems and duplicate
part identities before resetting the catalog. Follow the [upgrade runbook](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/UPGRADES.md#catalog-epoch-2-cutover).
Do not start the new application against an older catalog that has not been
prepared. To go back to an older release, restore its matching backup; changing
the application images alone is not enough.

## Release Studio

Release Studio takes a saved KiCad revision through **Source → Identity →
Manufacturing → Build → Outputs → Publish**.

- Choose the board, schematic, design variant, and KiCad BOM preset from that
  revision. You can also enter a full commit SHA to build an older revision.
- Set the release tag and drawing details before building. Prism checks whether
  the tag already exists and lets you choose manufacturing settings and
  manufacturer-specific output packages.
- Build fabrication files, assembly files, documents, and a release package
  containing the outputs and build records. Follow the build logs live, then
  inspect the PDFs and individual files.
- Designer and QA approvals apply to the exact release package they reviewed.
  DRC/ERC errors that have not been waived block approval unless an
  administrator records an override.
- Publish approved release packages and completed manufacturer packages to
  GitHub or GitLab Releases, including configured self-managed GitLab servers.
- Fix document cropping and placement, KiCad stroke lettering, and older
  testpoint references. A failed view is handled within the document output,
  and Git subprocess cleanup has time limits.

Signed policy evaluation, cryptographic attestations, and offline verification
remain outside this release. See [Release Studio](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/release-studio/README.md).

## Component catalog and Library Manager

The catalog now treats a component as a part that can have several symbol and
footprint combinations. Each revision keeps its own files, including 3D models
and other asset types. Released revisions cannot be changed. One combination
is the default for placement; other complete combinations can also be selected.

- Migration tools export non-CERN components before the epoch-2 catalog reset
  and restore them afterward. They check file contents and part identities.
- Component editing includes metadata, inventory, revision records, release
  review, available symbol/footprint combinations, and downloads from a chosen
  revision.
- Import Center separates library imports from project-component imports.
  Users can review and correct proposed components before accepting them, and
  import from selected projects or all projects.
- Live symbol and footprint previews let users select a pin and find its
  matching pad, or select a pad and find its matching pin.
- Workflow and role rules now have one definition. Older edits report conflicts
  instead of overwriting newer work. Catalog pages use consistent ordering,
  validation can resume, and jobs distinguish failures that cannot be retried.
- Catalog code has been split into smaller services while keeping the existing
  calling interface. Tests check the service boundaries and ensure the same
  inputs still produce identical output files.

See [Library Manager](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/LIBRARY_MANAGER.md) and [upgrades](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/UPGRADES.md).

## Desktop KiCad Remote Symbol Provider

- Updates the catalog search and component details, with live previews that
  require authentication and placement of the selected symbol/footprint pair.
- Loads further pages of results and cancels old searches when the query changes.
  Failed details and previews can be retried, and the panel shows when users
  need to sign in again.
- Keeps KiCad replies tied to the session that requested them and prevents
  duplicate placement requests. A failed request is no longer reported as a
  successful placement start.
- Limits the size of transfer logs and removes credentials from them.

See [Remote Symbol Provider](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/REMOTE_SYMBOL_PROVIDER.md).

## Design review and viewer tools

- Search for components and nets, move between selected objects, and follow
  matching objects across views.
- Toggle pad numbers and net names on pads, tracks, and vias under
  **Objects & filters**.
- Use Shift-click to highlight several nets. The selection panel lists them,
  and compatible 3D views highlight the same nets.
- Inspect routing statistics for each PCB net. Schematic and board net names
  are matched using their shared connections.
- Keep highlights when zooming in deeply. Labels remain readable during
  highlighting and are no longer rebuilt on every zoom.
- Fix the selection inspector, resizable panels, project-title layout,
  schematic redraws, overlapping 3D reloads, and selection when clicking empty
  space.
- Include the upstream ECAD viewer fixes through PR #43, which checks whether
  the objects referenced by comments are present in the loaded design.
  Net names inside filled zones remain removed.

See [project review](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/PROJECT_WORKFLOWS.md#pcb-labels-and-net-review).

## Design variants

- Show the variants available in the selected revision and keep the chosen
  variant in the URL so it can be shared.
- Apply that variant's assembly choices to the schematic, PCB, bill of materials
  (BOM), inspector, and search.
- Hide parts marked “do not populate” (DNP) in 3D, with a **Show DNP** option.
  Release Studio uses the same list of variants.
- Show separate messages for unknown variants, missing variant data, and failed
  loads. An unknown variant in a link stays in the URL while Prism shows the
  default assembly.

DNP settings from rule areas are reported but not applied. When alternate
footprints make a part's DNP status unclear, it stays visible with a notice.
Assembly Assistant still uses the reference assembly rather than the selected
variant. See [design variants](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/PROJECT_WORKFLOWS.md#design-variants).

## Live comments and issue publishing

- Update project and comparison discussions live, including across backend
  processes. After reconnecting, clients receive missed changes, with limits on queued
  updates. Regular refresh is available if live delivery fails.
- Keep the commit where a comment was created and a history of later changes
  to its location. If its object is missing or unclear, the comment remains
  available for review and can be attached again. Older comments without a
  recorded revision are clearly marked.
- Let administrators configure Git hosts, users connect their accounts, and
  projects choose where to publish issues.
- Publish threads to GitHub, GitHub Enterprise, GitLab.com, and self-managed
  GitLab. Sync replies and thread changes, and show progress or retry status.
- Encrypt stored connection credentials. Receive change notices from Git hosts
  and check them periodically, choose the appropriate host integration, and
  recover when a remote operation's response is lost.
- Supports GitLab and Gitea/Forgejo account linking. Gitea/Forgejo issue
  publication is not included.

Prism keeps the original comments, which remain usable when an issue tracker
is unavailable. Mentions do not create a Prism inbox or email notification. See
[live comments](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/architecture/live-comments.md), [GitHub setup](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/GITHUB_APP_SETUP.md),
[GitLab setup](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/GITLAB_SETUP.md), and [tracker operations](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/TRACKER_INTEGRATION.md).

## Git projects, history, and workspace

- Import multiple KiCad projects from one directory, keeping each project's
  identity and thumbnail separate. Resolve text variables in project details
  and title blocks.
- Fetch project remotes automatically every five minutes by default. Set
  `PRISM_AUTO_SYNC_INTERVAL_SECONDS=0` to disable background fetching.
- Show the latest remote branch commits consistently and read commit file trees
  that contain Git submodules.
- Decide what to import before cloning and registering projects. Users with
  permission can retry follow-up work that failed after an import.
- Open supported non-CAD files from a commit with their correct file types.
  Improve project paging, gallery layout, repository links, and refresh errors.
- Stop late responses from an old session or request from replacing the user's
  current workspace, import, or component selection.

## Comparison, authentication, and reliability

- Keep comparison selection and display settings in the URL. Improve layer
  isolation and navigation between matching objects, and make sure each side
  uses evidence from its own revision.
- Avoid repeatedly parsing the same comparison data, limit the cached data,
  and improve compressed responses and update polling.
- Add optional email/password login alongside OIDC single sign-on,
  administrator password resets, remember-me sessions, and login rate limits.
- Move slow authentication, comment, catalog-upload, and metadata work out of
  the shared request loop so it does not block other requests.
- Recover UI sections loaded on demand after a deployment, improve PDF previews,
  and strengthen checks for accessibility and stale UI updates.
- Back up the directories actually mounted by Compose and reject overlapping
  backup locations. Prepare restored files before replacing existing ones,
  restore PostgreSQL in one transaction, and report failures to stop or restart
  the application.

## Dependencies and experimental Rust support

- Use `kicad-monkey==2026.9.7` and `kicad-cruncher==2026.9.7`, with
  `wn-geometer==2026.9.7` in the Python dependency lock.
- Fix the versions of Python 3.12.13, Node 22.23.2, both npm dependency sets,
  the KiCad image, and the native helper's source and build tools. CI checks
  that the installed versions match.
- Include the experimental Rust path for PCB geometry, packed 3D meshes, and
  board-body generation. **Normal deployments use
  `PRISM_PCB_GEOMETRY_BACKEND=legacy`.** Rust and Python-copper require explicit
  selection; installing the helper does not activate them.
- Stop Rust processing if the helper fails, its identity does not match, or
  it encounters unsupported geometry. Faster benchmark results do not prove
  that its output matches the legacy path in every case. Component-model export
  still uses KiCad CLI.

See [dependencies](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/DEPENDENCIES.md) and [experimental geometry](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/PCB_RUST_GEOMETRY.md).

## Deployment and upgrade checks

This is an alpha release for Linux AMD64. The deployment archive identifies the
exact application images to use. Publication creates only the `4.0.0-alpha`
image tag; it does not update stable tags. The archive includes release notes,
upgrade instructions, backup tools, and checksums for verifying the files.
The main commit must pass the Quality gate, and the built release stack must
pass its smoke test before publication.

Before reopening an upgraded installation, check login, schematic/PCB/3D views,
variants, comparisons, comments and reconnects, catalog search, placement of
default and alternate symbol/footprint pairs, imports, Release Studio builds
and approvals, and any configured issue tracker. Keep the verified pre-upgrade
backup and the archive of preserved catalog components.
