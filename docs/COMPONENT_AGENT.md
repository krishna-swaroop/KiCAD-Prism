# Component agent (experimental)

Library Manager can research an exact manufacturer part number using an internal
OpenCode V2 runtime and an OpenAI-compatible model such as Gemma on Thor. It
produces a sourced ComponentSpec and deterministic review candidates. Engineers
attach candidates to new revisions, run catalog validation and inspect the
source pinout before requesting QA review. Approval and release use the existing
catalog workflow.

## Start the runtime

Generate a deployment secret with `openssl rand -hex 32` and put it in your
private environment file as `COMPONENT_AGENT_TOKEN`. The API, catalog worker,
and agent sidecar must use the same value. This is an internal service secret,
not a user service token. Do not commit it.

Set `PRISM_AGENT_MODEL_URL` to your OpenAI-compatible `/v1` endpoint and
`PRISM_AGENT_MODEL_ID` to its exact served alias. For the current Thor setup,
forward its loopback server to the Docker host:

```bash
ssh -N -L 18082:127.0.0.1:8080 swaroop@100.102.210.34
```

On Docker Desktop the overlay defaults to
`http://host.docker.internal:18082/v1`. On Linux, use an endpoint reachable from
the sidecar; a host tunnel bound exclusively to 127.0.0.1 is not reachable through
the Linux bridge gateway. Run the tunnel in the deployment network or set the
model URL to an explicitly reachable private endpoint.

```bash
docker compose --env-file .env \
  -f docker-compose.yml -f docker-compose.component-agent.yml \
  up -d --build
```

The overlay publishes no agent ports. OpenCode listens on the sidecar's loopback
4096; Prism's adapter listens on internal 4097 with bearer authentication. The
adapter handles OpenCode V2's generated Basic-auth password internally. Model
and search credentials stay in server environment variables.

OpenCode is pinned to 2.0.20 and Node to the repository's 22.23.2 runtime. The
sidecar has no database credentials, Prism asset mounts, Git identity, or KiCad
installation. Its only write tools submit research proposals into task-local
storage. Spec checking calls a pure, authenticated Prism endpoint. KiCad files
are generated by Python in Prism, and imported through existing catalog APIs.

Native OpenCode web search needs an available provider credential: `EXA_API_KEY`,
`TAVILY_API_KEY`, `FIRECRAWL_API_KEY`, or `PARALLEL_API_KEY`. Manufacturer HTTPS
URLs can be supplied directly without search. Missing source facts produce a
needs-input result instead of an invented pin map.

## Use Library Manager

- Choose **Component agent** to research from manufacturer and exact MPN only.
- In **New component**, select **Research symbol and footprint candidates after
  creation** to start a task bound to that record and its revision.
- An existing component also has a **Component agent** button. Its datasheet URL
  is suggested, and additional manufacturer URLs can be supplied.
- Watch progress, inspect source hashes, unit partitioning, findings and the full
  spec. Task identity is in the `agentTask` URL parameter for reloads/bookmarks.
- The **Model activity** panel streams Gemma's responses, thinking and
  tool status through an authenticated Prism event stream. Updates are batched
  roughly every two seconds as OpenCode updates messages, rather than individual
  token deltas; this is not a direct browser connection to the
  model. The bounded trace survives reloads, and closing the dialog closes its
  event stream without cancelling research.
- Download candidates or explicitly attach each candidate to the component.
  Attachment checks the expected current revision and component identity. A
  concurrent edit requires refreshing. Existing assets remain revisioned.
- Run the normal catalog validation and review the datasheet against every
  symbol pin and footprint pad. Then request QA through the existing workflow.
- For a needs-input question, start another attempt with the engineer's answer
  and source URLs in the instruction field. This creates a separate durable run.

Closing the dialog leaves the task running. Use **Cancel research** to stop it.
Prism jobs retain results, source manifests, model identity, thinking setting,
and a bounded tool/text trace. The agent volume retains downloaded sources and
session data for seven days by default (`PRISM_AGENT_RETENTION_DAYS`). Include
that volume in backups if source bytes must be retained longer; a source hash
alone cannot reproduce a changed manufacturer document.

## Boundaries of this first version

The generator supports multiple symbol units and axis-aligned SMD rectangular,
circular, and rounded rectangular lands. For capability tests, the agent makes
its best footprint attempt even when a manufacturer land pattern is unavailable.
It can estimate geometry from package dimensions, pitch, symmetry, and engineering
knowledge. Estimated geometry carries `{"status":"estimated","method":"..."}`
evidence describing the assumption. Missing land-size evidence and overlapping
pad bounding boxes appear as review warnings and do not prevent generation.
The dialog displays these assumptions alongside the downloadable candidates.
Unsupported geometry or structurally incomplete specs still produce findings.
A complete pin map can still produce a symbol candidate.
Through-hole, arbitrary rotations, distributor enrichment, uploaded catalog PDF
assets, and automatic metadata application are not implemented.

Text extraction/search is the default. Image page inspection is opt-in with
`PRISM_AGENT_MODEL_VISION=true`, after verifying that the chosen model server
handles image tool results. Gemma's Thor server exited during the initial image
trial; this option is disabled by default. `PRISM_AGENT_CONCURRENCY` defaults to
one, matching the current llama.cpp single-slot configuration. Thinking is chosen
per task; the runtime advertises a 262,144-token model context.

For local capability tests, set `COMPONENT_AGENT_TIMEOUT_SECONDS=0` to keep
research running until completion or cancellation, and increase
`PRISM_AGENT_MAX_STEPS` (default 200, local trial 1000). Validator repairs have
no fixed attempt cap. The blocking OpenCode wait uses native HTTP to avoid
Node fetch's independent five-minute response-header timeout. Operational
deployments can retain a finite research deadline; the default is 1800 seconds.

Spec checks verify identity, unique pins, full unit coverage, pin/pad coverage,
evidence references, fetched document hashes/URLs and page bounds. They do not
establish engineering correctness. Source pinout review stays **pending**, and
KLC stays **not run** until the normal catalog checker executes. No agent tool
can approve or release a component, and no structural check auto-submits to QA.
The tools expose the complete ComponentSpec schema. Submission checks return
repair instructions when no candidate can be generated; estimated footprints
and review warnings are accepted as proposals for engineering review.

The catalog is shared at the Prism workspace level. Tasks use catalog reader and
writer roles, matching existing catalog access. This API does not accept project
assets or provide a cross-project/private-tenant asset boundary.

## API and evaluation

- `POST /api/catalog/agent-tasks` starts a catalog-writer task.
- `GET /api/catalog/agent-tasks/{id}` returns status and candidate evidence.
- `GET /api/catalog/agent-tasks/{id}/events` streams model activity (SSE).
- `POST /api/catalog/agent-tasks/{id}/cancel` requests cancellation.
- `GET /api/catalog/agent-tasks/{id}/candidates/symbol|footprint` downloads a file.
- `POST /api/catalog/agent-tasks/{id}/attach/symbol|footprint` explicitly imports a
  candidate with `{expected_revision_id}`.

Prism-AI's `python3 -m prism_ai.agent` captures attempts through this authenticated
Prism API. Reference KiCad files and independently reviewed pin maps stay in the
evaluation harness, outside the model's task. Captures are unreviewed; approved
components and expert corrections must be separate training labels.

Runtime contracts follow the official [OpenCode V2 HTTP API](https://opencode.ai/v2/docs/api)
and [standalone server documentation](https://opencode.ai/v2/docs/cli/web).

## Initial live baseline (2026-09-30)

Two no-thinking runs against Thor's Gemma BF16 endpoint fetched TI's
SN74LVC1G14 datasheet using a supplied manufacturer URL. The first returned
needs-input for missing lands. After clarifying partial symbol output, the
second proposed five pins but used an invalid schema version and omitted pads;
Prism rejected it and generated no candidate files. These are captured in
Prism-AI's `examples/agent-attempts/` as unreviewed attempts. Neither establishes
pinout correctness, part-number-only web discovery, or complex FPGA competence.
The current setup still needs a search provider credential to test MPN-only
internet discovery. These captures are not fine-tuning labels.

Local implementation checks passed: 2,156 backend tests (15 existing skips),
908 frontend tests, 3 runtime adapter tests, frontend lint/build/panel build,
React Doctor (zero warnings/errors), catalog architecture checks, optional
Compose configuration and the agent Docker build. Prism-AI's 12 tests passed.
KiCad parsed/rendered both units of a synthetic symbol and its footprint. A
synthetic proposal attached through the new endpoint as two new catalog
revisions; stale revision requests returned 409 and the component stayed open.
This attachment fixture is independent of the two rejected Gemma attempts.
The full backend suite used a fresh dedicated PostgreSQL test database and
`PUBLIC_BASE_URL=https://prism.example`; reusing the database retained identities
from unrelated import tests. These are local checks, not a CI or production
deployment claim.
