# Release Studio R0 fixtures

R0 provides three durable, repository-local KiCad designs and deterministic CLI
records for later Release Studio chunks. Every design manifest is
`fixtures/release-studio/<name>/fixture.json`; its `entrypoints` object is the
authoritative map for the project, board, schematic, and jobset files.

## Fixture entrypoints

| Fixture | Project | Board | Schematic | Jobset |
| --- | --- | --- | --- | --- |
| `synthetic` | `synthetic/synthetic.kicad_pro` | `synthetic/synthetic.kicad_pcb` | `synthetic/synthetic.kicad_sch` | `synthetic/synthetic.kicad_jobset` |
| `usb-pd` | `usb-pd/USB-PD-Trigger-Board.kicad_pro` | `usb-pd/USB-PD-Trigger-Board.kicad_pcb` | `usb-pd/USB-PD-Trigger-Board.kicad_sch` | `usb-pd/Outputs.kicad_jobset` |
| `cynthion` | `cynthion/cynthion.kicad_pro` | `cynthion/cynthion.kicad_pcb` | `cynthion/cynthion.kicad_sch` | `cynthion/cynthion.kicad_jobset` |

The USB-PD schematic's `Subsheets/Output-Connector.kicad_sch` and all sixteen
Cynthion child sheets are committed alongside their parent entrypoints. Their
library tables resolve only to fixture-local libraries. Jobsets contain local
schematic PDF jobs and, where configured, BOM/DRC jobs; none uses an external
plugin or generated-directory dependency.

## Synthetic variants

The synthetic design has exactly three explicit named variants. There is no
metadata-only default and no implicit baseline counted in R0:

| Name | Schematic/board population |
| --- | --- |
| `default` | `D1` and `R1` populated |
| `dnp-led` | `D1` DNP; `R1` populated |
| `assembly-reduced` | `D1` and `R1` DNP |

The names are intentionally repeated in the real KiCad carriers and in
`synthetic/fixture.json`:

- `synthetic.kicad_pro` stores the project catalog in
  `schematic.variants`.
- `synthetic.kicad_pcb` stores the board catalog in `(variants ...)` and the
  per-footprint `(variant ...)` DNP overrides on `D1` and `R1`.
- `synthetic.kicad_sch` stores the per-symbol-instance `(variant ...)` DNP
  overrides inside the `instances/project/path` blocks for `D1` and `R1`.

Thus the assembly change is population-only: the same board artwork and
schematic symbols remain present while the variant-aware BOM changes the
included references.

## CLI recordings and live behavior

`fixtures/release-studio/cli-recordings/{synthetic,usb-pd,cynthion}.json` uses
schema version 1. Each record contains a normalized successful KiCad CLI
command, exit code, scrubbed stdout/stderr, and stable semantic output fields.
`<fixture>` and `<output>` are placeholders, not paths. Records contain no
timestamps, machine paths, secrets, or generated output trees.

`backend/tests/release_studio_support.py` exposes the fixture helpers and the
shared `requires_kicad_cli()` unittest seam. In the ordinary host job, a live
test skips only when `kicad-cli` is unavailable. When
`PRISM_RELEASE_EXECUTOR_IMAGE` is present, it must match the baked identity at
`/etc/prism/kicad-base-image` (the R00a Dockerfile contract), including a
trailing `@sha256:<64 lowercase hex>`. Missing CLI, a non-10.0.4 version, a
baked/env mismatch, or an unexpected skip fails the live test.

The live suite executes each jobset with `kicad-cli jobset run --stop-on-error`,
parses all three boards and schematics, then exports `default`, `dnp-led`, and
`assembly-reduced` synthetic BOMs with `--exclude-dnp` and checks the expected
reference sets. Live commands run from temporary fixture copies so KiCad
preference/lock files never alter the committed sources.

`backend/tests/release_studio_live_runner.py` runs the R00a identity module, this
fixture module, and the R4 canonicalization semantic module; CI mounts
`fixtures/release-studio` at `/fixtures/release-studio` because the backend
image flattens under `/app`. The strict runner fails on any skip, so the R4
KiCad-generated semantic tests cannot silently disappear from the live gate.

## Validation commands

Host-safe fixture, recording, and variant checks (the only permitted result is
the documented ordinary-host live-test skip when the CLI is absent):

```sh
cd backend
python -m unittest tests.test_release_studio_fixtures -v
```

Pinned live runner (rebuild or mount the updated tests; fixtures must be at
`/fixtures/release-studio` inside the container):

```sh
BAKED="$(docker run --rm --entrypoint /bin/cat release-studio-live-kicad:ci /etc/prism/kicad-base-image | tr -d '\r\n')"
docker run --rm --platform linux/amd64 \
  --env "PRISM_RELEASE_EXECUTOR_IMAGE=${BAKED}" \
  --volume "$PWD/fixtures/release-studio:/fixtures/release-studio:ro" \
  --volume "$PWD/backend/tests:/app/tests:ro" \
  --entrypoint /app/venv/bin/python \
  release-studio-live-kicad:ci \
  -m tests.release_studio_live_runner
```

Source hygiene and Python compilation:

```sh
git diff --check
python -m compileall -q \
  backend/tests/release_studio_support.py \
  backend/tests/test_release_studio_fixtures.py \
  backend/tests/test_release_studio_live_ci.py \
  backend/tests/release_studio_live_runner.py
```
