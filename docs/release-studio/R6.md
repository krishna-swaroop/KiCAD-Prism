# Release Studio R6: configuration spec and technical/policy split

R6 loads release configurations from `.prism/release-studio/`, applies strict
`{{namespace.key}}` substitution, and separates the technical configuration
digest from the policy binding.

## Owned surface

| Path | Role |
| --- | --- |
| `backend/app/release_studio/config/` | Schema, loader, substitution, digests |
| `backend/tests/test_release_studio_config.py` | Acceptance tests |
| `backend/requirements.txt` | Adds `PyYAML` for configuration YAML |
| `docs/release-studio/R6.md` | This note |

## Configuration contract

Files live at `.prism/release-studio/configurations/<key>.yaml` with schema
`prism.release-studio.configuration/1`. Unknown keys are rejected by name.
Required fields: `title`, `board`, `schematic`, `jobset`.

All configuration file references are POSIX, repository-root-relative paths.
`board`, `schematic`, `jobset`, and schematic entries in `sheets` must use
their KiCad file extensions; `template` is also repository-relative. Absolute
paths, `..` components, Windows path forms, and checkout symlinks that resolve
outside the checkout are rejected.

Org policy references must be pinned: `org:<key>@<version>`. An unpinned
`org:<key>` is a load error. A local overlay is referenced either directly as
`.prism/release-studio/policies/<key>.yaml` or with a mapping such as
`{path: .prism/release-studio/policies/<key>.yaml}`; it must be a direct YAML
file in that directory. Checkout and commit loading resolve the same
repository-relative object, including safe in-repository symlinks.

`load_configuration_from_checkout` and `load_configuration_at_commit` must
return the same normalized mapping for the same tree.

## Substitution

`substitute_string` / `substitute_value` replace `{{fields.revision}}`-style
tokens only, where each token path is an identifier separated by dots.
Missing keys raise `SubstitutionError` (never blank). Unmatched, extra, or
nested braces are rejected, and replacement text is not scanned recursively.

## Technical / policy split

```text
technical_config_digest = H(canonical(config MINUS policy))
```

Canonical JSON uses recursive Unicode NFC normalization,
`sort_keys=True`, `separators=(",",":")`, `ensure_ascii=False`, and
`allow_nan=False`; NFC-normalized key collisions are rejected. The technical
digest uses an explicit technical-key allowlist and governance-key set, so a
new configuration key must be classified before it can affect a digest.
Changing only the policy reference must leave `technical_config_digest`
unchanged.
