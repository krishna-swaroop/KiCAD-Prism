# Release Studio R4: canonicalization registry

R4 defines the released-byte canonicalizers and the canonical JSON encoder used
by digests and manifests.

## Owned surface

| Path | Role |
| --- | --- |
| `backend/app/release_studio/canonical/` | Registry + per-type canonicalizers + `json.py` |
| `fixtures/release-studio/canonical-samples/` | Minimal generated samples |
| `backend/tests/test_release_studio_canonicalization.py` | Acceptance tests |
| `docs/release-studio/R4.md` | This note |

## Rules

Released dossier members are the canonicalized bytes. Each canonicalizer may only
remove or normalize non-manufacturing metadata:

- Gerber: drop `%TF.CreationDate…*%`, keep `%TF.GenerationSoftware`
- `.gbrjob`: drop `GeneralSpecs.CreationDate`, re-emit sorted JSON
- Excellon: drop `; DATE` / creation comment headers
- STEP: replace `FILE_NAME(...)` path/timestamp argument with sentinel; `DATA;` unchanged
- CSV: drop generated-on header rows; normalize newlines/trailing whitespace
- DRC/ERC JSON: drop report timestamp; stable-sort violations
- SVG: strip date comments and `<metadata>`
- Board stats JSON: drop `metadata.date`
- PDF: optional via `pikepdf` (`deterministic_id`); raises if unavailable
- Archive: own tar writer (`mtime=0`, uid/gid 0, empty uname/gname, sorted members, gzip `mtime=0`)

Canonical JSON (`canonical_json` in `encoding.py`) uses `sort_keys=True`,
`separators=(",",":")`, `ensure_ascii=False`. This deliberately differs from
`JobArtifactService.prepare_json`, which omits `sort_keys`.
